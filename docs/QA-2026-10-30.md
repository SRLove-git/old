## 初检问题清单（修复前）

### 1. P1：线上仍接受联调身份头，生产模式还有匿名身份错误

位置：`server/src/middleware/auth.js:96-100`。

线上进程未设置 `NODE_ENV`。无 token 访问订单接口返回 401，但只加入合成的、数据库不存在的 `x-user-id` 后，`/api/orders` 与 `/old-api/api/orders` 均返回 200 空列表。此验证没有使用真实会员 ID 或读取他人订单；结合源码可确认接口仍接受客户端指定的旧联调身份。

同时，在隔离环境设置 `NODE_ENV=production` 后，`legacyAllowed && ...` 得到布尔 `false`，后续被转换成非空字符串 `"false"`。匿名建单因此成功并占用库存。不能仅修改部署环境变量，必须一并修正身份解析，默认只信任签名会话。

### 2. P1：订单查单接口可跨业务类型返回他人记录

位置：`server/src/routes/orders.js:41-44`、`server/src/middleware/auth.js:111-115`、`server/src/services/payments.js:64-66`。

订单 ID 未命中订单表时，归属校验直接返回；支付刷新逻辑又会查找充值单、主理人申请。隔离环境用有效签名的模拟微信查单响应，复现了匿名读取其他用户充值记录及含手机号的主理人申请。

前提是持有可向微信成功查单的相应业务 ID。本轮没有查询真实生产支付单。修复应同时校验记录存在、业务类型及所属会员，并限制返回字段。

### 3. P1：会员码、主理人推广码尚未生成真实二维码

位置：`miniprogram/utils/qrcode.js:1`；调用处 `pages/member-code/member-code.js:90`、`pages/manager/manager.js:255`。

当前工具通过哈希随机生成黑白矩阵，注释也说明用于演示，未实现二维码编码与纠错。外观像二维码，但不能完成正常扫码。会员码应使用真实编码实现，推广入口应采用与业务匹配的有效小程序码/二维码，并验证扫码后的身份和归属流程。

### 4. P2：低权限员工可查看物流异常中的收件信息

位置：`server/src/lib/permissions.js:35-37`、`server/src/index.js:339`。

物流路径缺少权限映射，落入默认无需专门权限分支。隔离环境仅有 `dashboard.view` 的账号成功读取含收件人手机号的物流异常记录。应明确物流读取和管理权限，避免未映射路径默认放行。

### 5. P2：商户更换商品封面后仍可能显示旧图

位置：`merchant/src/App.vue:336`、`server/src/store.js:4047-4048`。

上传新封面只更新 `coverImage`，旧 `images[0]` 仍保留。保存时服务端用第一张轮播图覆盖封面，导致接口保存成功但新图未生效。隔离回归已复现由新图 B 回退到旧图 A。需统一封面与轮播首图的数据规则。

### 6. P2：后台发货后，小程序物流页可能继续显示待发货

位置：`miniprogram/pages/logistics-query/logistics-query.js:69`。

查询只刷新用户资料，随后使用缓存订单，未刷新订单列表。模拟服务端已发货、缓存仍待发货时，页面直接提示等待商家发货。应在判断订单发货状态之前获取最新订单，并提供正确的轨迹刷新路径。

### 7. P2：物流旧扩展状态会阻止签收状态推进

位置：`server/src/store.js:2532-2534`、`:2547-2550`。

先收到 `State=2, StateEx=202`，后收到 `State=3` 且不带 `StateEx` 时，旧扩展状态被保留，仍被识别为派送中，订单未从待收货推进待评价。隔离测试已复现。线上物流记录当前为 0，因此本项是潜在功能缺陷，不能据此断言某个真实包裹已异常。

### 8. P2：余额页顶部余额与最新流水可能不一致

位置：`miniprogram/pages/balance/balance.js:53`。

页面刷新了流水，但顶部使用缓存用户余额。模拟迟到回调或其他终端操作后，顶部为 10.00，最新流水余额为 100.00。应在进入页面及充值完成时同步刷新会员余额和流水。

### 9. P2：会员资料慢加载后不重绘会员码

位置：`miniprogram/pages/member-code/member-code.js:53`。

二维码仅在 `onReady` 绘制。资料异步加载或入会后会员号变化时没有重新绘制，可能一直展示空内容或旧会员号。应在有效会员号改变且画布就绪后重绘，与真实二维码修复一并验收。
